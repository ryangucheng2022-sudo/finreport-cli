# finreport

[English](README.md) | 简体中文

给一个公司名称，取回这家公司的正式财报全量数据。单文件命令行工具，面向 **A 股上市公司**：从东方财富 F10 结构化接口取数，生成完整工作簿——关键指标、**利润表/资产负债表/现金流量表全表**（本期 vs 上年同期），以及由累计数差分出的单季数据。

**只用正式财报**（季报、半年报、年报）；业绩预告、快报、指引、预测数一律不入。

## 谁在用、用它做什么

| 角色 | 典型场景 | 价值点 |
|---|---|---|
| **财务人员** | 财报季核对同行或上市子公司报表；审计、尽调资料包准备；月度经营分析取数 | 三大报表全表一次到位、两期自动对照，不再逐份下载 PDF 翻页抄数；每个数字可回溯到结构化数据源，工作簿自带口径说明，勾稽有据 |
| **战略与经营分析人员** | 竞争对手跟踪；并购/投资标的初筛；行业对标与董事会材料准备 | 任意 A 股几秒钟出全量数据，不受固定名单限制；单季拆分看清最新单季的真实动能，而不是累计平均；同比与增减自动算好，直接进入分析 |
| **投资研究人员** | 财报季批量跟踪覆盖公司；业绩发布后快速复盘；可比公司表搭建 | 只认正式披露，预告/快报/预测按规则排除，预测数不会污染实际数；JSON 输出可直接喂给自己的模型与数据流水线 |
| **管理层、董办与 IR** | 临时问答（「友商最新一期毛利率、存货周转怎么样」）；路演与监管问询准备 | 结论数即问即得且可审计；没披露就是没披露，绝不拿估算填空糊弄决策 |
| **开发者与 AI Agent** | 把财报取数接进内部智能体、RPA 或数据管道 | 单文件、一个依赖、JSON 进出；名称有歧义时显式返回候选、绝不猜数——为自动化设计的确定性行为 |

## 为什么不直接下载公告 PDF

- **结构化而非抄录**：数据来自与数据终端同源的结构化接口，没有 OCR 和转录错误。
- **口径统一**：累计与单季严格分开标注；周转天数采用经与公告勾稽验证的披露口径，而不是本地近似重算。
- **开箱即比**：本期/同期、同比、百分点增减，对每家公司用同一套算法算好。

## 快速开始

```bash
finreport report 圣邦股份                    # 最新披露期
finreport report 600519                      # 也可以直接给 6 位代码
finreport report 贵州茅台 --date 2026-06-30  # 指定报告期
finreport report 中国平安 --json-only        # 只出 JSON 摘要
finreport resolve 中国平安                    # 只做名称解析
```

- 名称解析：精确简称唯一命中；多家命中（如「平安」）返回候选列表，**不猜**。
- 默认期间：最新正式披露期，对比期为上年同期。
- 输出：JSON 摘要（两期关键指标、单季拆分、工作簿路径）＋ Excel 六页工作簿——说明（口径与来源链接）、关键指标、利润表、资产负债表、现金流量表、单季拆分；金额单位千元。
- 报表中未收录的科目保留字段代码原样展示，不丢弃、不臆造翻译。

## 环境

- Python 3.9+；唯一第三方依赖 openpyxl（生成工作簿）。
- A 股公司列表（约 5,900 家）缓存在 `~/.finreport/stock_list.json`（24 小时）；首次拉取约 1–2 分钟，之后秒级。

## 校验记录

与已定版的友商监控工作簿逐格勾稽（某半导体公司 2025 年 1–9 月累计：收入、毛利、毛利率、扣非净利润及三项周转天数全部一致）；跨行业实测覆盖消费与金融（银行/保险科目结构）公司。
